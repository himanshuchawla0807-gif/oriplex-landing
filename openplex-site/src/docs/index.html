OPENPLEX DOCUMENTATION

Start small.
Build something good.

One character. One folder. One useful task. Here’s how to get your first OpenPlex agent working on your Mac.

OpenPlex is a free, open-source beta. The downloadable app is ad-hoc signed and not Apple notarized. macOS may block first launch. Your chosen harness’s model usage is separate.

01. Download OpenPlex

The prebuilt beta supports Apple Silicon Macs (M1 or newer), macOS 13 or newer. It does not support Intel Macs. You don’t need Node.js or Swift to launch this download; the coding harness you install separately may need its own runtime.

Download Mac beta ↓

  1. Open the downloaded DMG.
  2. Drag OpenPlex.app to Applications.
  3. Eject the disk image, then open OpenPlex from Applications.
  4. Install and sign in to a supported harness, then choose your workspace folder in OpenPlex.

Signing limitation: this beta has an ad-hoc integrity signature, without Developer ID signing or Apple notarization. macOS may prevent it from opening. Keep Gatekeeper enabled. Review Apple’s guidance for opening trusted apps, or use the source-build instructions below if you do not want to approve an unnotarized beta. This is not a security certification.

Download the SHA-256 checksums or view the release notes.

Prefer to build from source?

You’ll need macOS 13 or newer, Node.js 24 or newer, npm, and Apple’s Swift command-line tools. The first clone includes a few hundred megabytes of illustrated character assets.

Check your tools in Terminal:

node --version
npm --version
swift --version

If Node.js is missing, install a supported version from nodejs.org. If Swift tools are missing, run xcode-select --install and finish Apple’s installer before continuing.

git clone https://github.com/himanshuchawla0807-gif/OpenPlex.git
cd OpenPlex
npm ci
npm run app:build
open output/OpenPlex.app

This creates a local app for your Mac’s architecture. It does not install a provider’s CLI or buy any model credits. The local build is ad-hoc signed, not Developer ID signed or notarized. Keep macOS security protections enabled.

Want to look around first?

Run the interface in your browser:

npm run dev:builder

Open http://127.0.0.1:5180/?builder. This preview has separate local storage and cannot launch the Mac app’s native terminals or native folder picker.

02. Bring your harness

A harness is the coding agent that powers a character. OpenPlex supplies the workspace and configuration; the selected CLI supplies the model connection and tools.

Codex

Follow the official Codex CLI guide. One installation option is:

npm install -g @openai/codex
codex

Finish its sign-in flow and test a small request in a normal terminal first. OpenPlex uses the existing harness authentication. Do not paste credentials into a profile or commit them to the repository.

Claude Code

Follow the official Claude Code setup guide, sign in through Claude Code, and check that a request works outside OpenPlex. Reopen OpenPlex after installing a new harness.

The app looks for supported executables in ~/.local/bin, /opt/homebrew/bin, and /usr/local/bin. A shell alias alone is not an executable the app can launch.

CapabilityRelease scope
Streamed work & status reportingCodex and Claude Code
Conversational employee builderCodex, Claude Code, and tool-denied OpenCode text generation
Other CLI catalog entriesAdapter-specific support, including setup-only entries

See the repository’s adapter notes for the full distinction. A catalog entry is not a claim of authenticated compatibility.

03. Choose a folder and a character

  1. Open the Mac app. Choose Light, Dark, or System appearance.
  2. Create an office. Start with a furnished campus or add one room.
  3. Choose Add a person, pick a character, and set a name and role.
  4. Select your harness. Choose a workspace folder through the app’s folder picker before connecting or using the builder.
  5. Open the agent’s workspace and choose Connect Codex or the corresponding harness button.

The selected folder is the workspace for this project. OpenPlex creates employee-scoped configuration under .openplex/employees/. Choose a folder you understand and keep edits disabled for your first task.

Try a small, checkable request:

Review the README and list three unclear setup steps.
Do not edit files.

Review the answer and its evidence before giving a broader task or enabling more capabilities.

04. Give the character a purpose

Choose Build your employee with chat to describe the role conversationally, or edit the profile directly. Bring useful files, examples, and instructions, then review the resulting profile before saving.

Profile areaWhat belongs there
ProfileName, role, and system prompt: what this agent is here to do.
InstructionsHow it should work, review criteria, and project-specific context.
SkillsEmployee-scoped skill files and references relevant to the job.
MCPExact server configuration. Review the command and grant first-use trust only when you understand it.
PluginsPlugin references. Saving a link does not install or verify the plugin.
HarnessThe supported installed CLI that runs this agent.

Integration setup needs an actual connection test. Saved content, installed tools, and verified working tools are different states. Review unknown MCP commands independently before approving them.

05. Work in Chat or Terminal

Chat shows supported harness output as readable turns. Terminal exposes the actual interactive CLI session. Switching between them changes the view of that employee’s session, not the task you are running. Vendor output that cannot be projected cleanly remains available in Terminal and diagnostics.

In Team workspace, filter by working or connected agents, search names, choose one to eight panels, and resize the divisions. The Scroll button switches horizontal and vertical scrolling. New space groups a few agents into a view; it does not change their identity or permissions.

Start a new conversation

Interrupt active work first, then use New chat. The next conversation starts fresh with the same saved role, system prompt, instructions, and configuration. Old app archives and vendor CLI transcripts have separate retention; starting fresh is not secure erasure.

Stop a task

Use Interrupt to stop current work. Use End session when you are done. A terminal’s connected state does not mean that a task is actively running.

06. Catch up with Office Communicate

Open Office Communicate from the office or Team workspace. The audience preview shows who will receive the request before you send it.

  • “What’s going on?” in all-hands asks the hired agents in the selected office.
  • “Oscar, what’s going on?” asks that agent by name.
  • “Technical department, what’s going on?” narrows the request to that department.

Supported adapters make a separate reporting request with a bounded snapshot of the employee’s recent work. Replies appear in the local feed and link back to their source conversation. The working session is not replaced by the report request.

Missing work evidence and unsupported adapters are shown explicitly. Reports consume the selected provider’s usage. This is a local status feed, not a multi-user chat server or an autonomous management system.

07. Know the privacy boundaries

OpenPlex’s offices, profiles, and app conversations are saved on your device. There is no OpenPlex account or hosted sync service. The Mac app serves its bundled interface on loopback.

Cloud-backed harnesses still send prompts and context to their providers. Attachments, instructions, shared snapshots, MCP servers, vendor plugins, and telemetry each have their own data paths and policies. The app’s UI protections do not sandbox every child CLI.

Local storage is not app-encrypted. Builder chats expire after 30 days of inactivity; other archives and profile revisions have their own bounds. New chat does not erase vendor history. Deleting an office does not delete its project folder, provider transcripts, or backups.

Read the full privacy notes and security policy. The landing page itself has no analytics, trackers, account form, or third-party font requests; its hosting provider still receives ordinary web requests.

08. If something doesn’t connect

“Choose a folder before starting the builder”

Use the workspace folder button in the Mac app and select an existing directory. The browser preview cannot grant native folder access.

The CLI is not found

Check that the actual executable is installed in a supported location, test it in Terminal, then reopen OpenPlex. An interactive alias or a shell-only PATH may not be visible to the app.

A sign-in, allowance, or provider error

Run a request in the vendor CLI itself. Resolve login and quota issues through that tool’s own controls. OpenPlex does not bypass provider limits.

A black patch, missing reply, or rendering issue

Try the other view, note the harness version, theme, and steps that reproduce it, and open an issue with a redacted screenshot. Never attach tokens or private transcripts.

The local port is already in use

Close duplicate OpenPlex instances. The bundled app uses a stable loopback origin; the browser preview uses port 5180 by default.

An MCP configuration fails

Test the server independently and check the exact configuration. Do not approve an unknown command just to remove an error indicator.

09. Update or remove OpenPlex

End running sessions before rebuilding. Keep your office data and workspace files backed up separately. If you changed source files, commit or preserve those edits before pulling.

git pull --ff-only
npm ci
npm run app:build

Reopen the newly built output/OpenPlex.app. To stop using it, quit the app and remove that local app bundle. Workspace configuration, WebKit storage, vendor harnesses, their sign-ins, and their histories are separate; removing the bundle does not erase them. Do not delete a project folder just to uninstall OpenPlex.

Make a little room for your ideas

Report reproducible bugs, improve documentation, or contribute code. Read CONTRIBUTING.md before opening a pull request. For suspected vulnerabilities, follow the security policy instead of posting sensitive details publicly.

The release verification record describes tested behavior and remaining gates. Autonomous hierarchy and shared/vector memory are future v2 work.
